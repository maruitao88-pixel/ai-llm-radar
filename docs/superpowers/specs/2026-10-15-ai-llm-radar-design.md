## 1. 背景与目标

这是一个**个人自用**的 AI 大模型动态站。核心目标不是做资讯门户，而是回答两个问题：

1. 最近 AI 大模型发生了什么？（今日速览）
2. 哪些是真正改变格局的里程碑？（重大事件时间线）

现有开源项目里没有现成的"LLM 重大事件"站点，但 `AI-Search` 已经解决了抓取、去重、静态导出、自动部署、零服务器这一整套工程问题。本设计**不重写底座**，只在其上增加一层「显著性评分」，把信息流分流成"速览"和"里程碑"。

### 成功标准

- 打开首页 5 秒内能看清：今天有什么、最近有哪些大事。
- 每天自动更新一次，无需人工干预。
- 时间线里的每一条都是真事件，不是噪声。宁可少，不可滥。
- 全年零服务器成本，除 LLM 调用外无其他费用。

## 2. 范围

### 做

- 首页双栏：左「今日速览」信息流，右「重大事件时间线」。
- 新增 AI 显著性评分（0–100 分）+ 事件类型 + 一句话影响点评。
- 按分数自动分流：≥ 阈值进时间线，其余进速览。
- 新增「重大事件」全量页，支持类型与时间筛选。
- 每日 GitHub Actions 自动抓取、评分、构建、部署。
- 评分失败时规则兜底，保证站点永不为空。

### 不做

- 不做登录、评论、投稿、用户系统。
- 不做多语言切换（界面只有中文）。
- 不做数据库、后端服务、推送通知、移动 App。
- 不做人工审核后台。

## 3. 总体架构

沿用底座的静态架构，只在抓取流水线中间插入一个评分环节。

```
每日 22:17 UTC（北京 06:17）
        │
        ▼
  并行抓取各来源 adapter
        │  单源失败不影响整体
        ▼
  归一化 → 去重 → 历史合并 → 热度计算
        │
        ▼
  ★ 显著性评分（新增）        ← LLM 打分，失败降级为规则打分
        │
        ▼
  写入 data/items.json（新增 significance 字段）
        │
        ├─→ 静态构建（Next.js export）
        │        │
        │        ├─ 首页：速览 + 时间线双栏
        │        └─ /milestones：重大事件全量页
        │
        └─→ 部署 GitHub Pages
```

关键决策：**单一数据源**。不额外生成 `milestones.json`，时间线直接从 `items.json` 里筛 `significance.score >= 阈值` 派生，避免两份数据不一致。历史时间线由底座已有的月度归档（`data/archive/YYYY-MM.json`）自动覆盖。

## 4. 数据模型

在 `lib/types.ts` 的 `AIItem` 上新增一个可选字段：

```ts
export type EventType =
  | "model-release"   // 新模型发布（GPT、Claude、Gemini、Qwen…）
  | "capability"      // 能力突破（推理、多模态、长上下文、Agent、SOTA）
  | "funding"         // 重大融资、并购、估值
  | "policy"          // 政策法规、监管、出口管制
  | "opensource"      // 重量级开源项目 / 开放权重
  | "other";          // 其他重大行业事件

export interface Significance {
  /** 0-100 显著性评分。 */
  score: number;
  /** 事件类型标签。 */
  type: EventType;
  /** 一句话中文影响点评，≤ 60 字。 */
  reason: string;
  /** 分流结果，避免每次渲染重复比较阈值。 */
  verdict: "milestone" | "daily";
  /** 打分方式，便于排查与回溯。 */
  method: "ai" | "rule";
  /** 打分所用模型，规则打分时为 null。 */
  model?: string | null;
  /** 打分时间（ISO）。 */
  scoredAt: string;
}

export interface AIItem {
  // …既有字段不变…
  significance?: Significance | null;
}
```

`aiNote` 字段保留，继续作为卡片上的一句话点评显示。

## 5. 评分流水线

新增 `scripts/lib/significance.ts`，在 `scripts/crawl.ts` 的热度计算之后、写入快照之前执行。

### 5.1 输入

每条待评分条目的信息：标题、摘要、来源名、来源权威等级（`tier`）、发布时间、热度值 `heat`、原始互动量 `engagement`。同时传入同题条目的去重来源数（多源报道是重要信号）。

### 5.2 判定标准（写进 system prompt）

- 新模型发布，尤其是前沿实验室的旗舰模型。
- 能力突破：在权威基准上显著领先，或出现此前做不到的能力。
- 重大融资 / 并购 / 估值变化。
- 政策法规、监管、出口管制等影响行业走向的动作。
- 重量级开源或开放权重发布。
- 反例（不给高分）：常规产品更新、小版本迭代、单篇普通论文、观点文章、教程、传闻与未证实爆料。

### 5.3 调用策略

- 一次调用同时产出 `score`、`type`、`reason` 和一句话点评 `aiNote`，**替换**底座现有的 `addAiNotes` 单独调用，避免同一批内容调用两次、成本翻倍。
- 批量打分：每批 10 条，一次请求返回 JSON 数组，显著降低 token 消耗。
- 只处理 `significance` 为空的条目（缓存命中即跳过），重复运行不重复计费。
- 并发 4，单请求超时 30 秒，失败重试 1 次。
- 每日评分上限 `SIGNIFICANCE_MAX`（默认 60 条），超额条目走规则打分，成本封顶。

### 5.4 分流

- `score >= SIGNIFICANCE_THRESHOLD`（默认 80）→ `verdict = "milestone"`，进时间线。
- 其余 → `verdict = "daily"`，只进速览。

阈值是可调的一号旋钮。上线首周观察时间线密度，再决定是否上调或下调。

### 5.5 规则兜底

无 API Key、调用失败或 JSON 解析失败时，用确定性规则打分：

| 信号 | 分值 |
| --- | --- |
| 来源权威等级 tier 1 / 2 / 3 | +40 / +25 / +15 |
| 命中重大关键词（发布、推出、launch、release、SOTA、融资、billion、监管、regulation、开源权重…） | +30 |
| 热度进入当日前 10% | +20 |
| 同一事件被 3 个及以上来源报道 | +10 |

封顶 100 分。按此规则，"官方来源 + 重大关键词"得 70 分（40+30），单靠它到不了默认 80 分阈值；要进场需再叠加"热度前 10%"（+20 → 90 分）或"多源报道"（+10 → 80 分）。天然抑制刷屏。规则打分条目 `method = "rule"`，界面上与 AI 打分不做视觉区分，但可在数据中区分。

## 6. 界面设计

### 6.1 首页双栏布局

```
┌────────────────────────────────────────────────────────────┐
│  Header · 导航 · 更新时间                                   │
├──────────────────────────────────┬─────────────────────────┤
│  今日速览                         │  重大事件时间线          │
│  ─ 过滤 / 排序 / 搜索             │  ─ 按日期倒序            │
│  ─ 卡片流（无限分批加载）          │  ─ 类型标签 + 标题       │
│                                  │  ─ 一句话影响            │
│                                  │  ─ 来源链接              │
│                                  │  [查看全部 →]            │
└──────────────────────────────────┴─────────────────────────┘
```

- 栅格：`lg:grid-cols-[minmax(0,1fr)_360px]`，桌面右栏固定 360px。
- 中等屏（`md`）：单栏，速览在前、时间线在后。
- 小屏：保持速览 → 时间线的顺序；速览采用分页加载，避免把时间线推到很远。
- 右侧时间线默认显示最近 8 条，底部「查看全部」跳 `/milestones`。

### 6.2 时间线组件

新增 `components/MilestoneTimeline.tsx`，被首页右栏和 `/milestones` 页共用，通过 `variant="compact" | "full"` 区分。

每条包含：日期、事件类型标签、标题、一句话影响点评、来源名与链接。

- 按日期倒序分组，同日多条按分数降序。
- `/milestones` 页顶部提供类型筛选（全部 / 模型发布 / 能力突破 / 融资 / 政策 / 开源）和年份筛选。
- 空状态：文案「暂无重大事件」并说明阈值，不留白。

### 6.3 视觉与动效规范

- 配色：白底黑字，蓝色为唯一强调色；类型标签使用蓝 / 靛 / 青 / 石板等冷色系区分。
- 红色仅用于错误、警告、失败语义，不用于任何正常状态或类型标签。
- 图标使用统一的线性图标库（沿用底座依赖或引入许可清晰的图标包），不使用 emoji 充当图标；所有图标提供无障碍名称。
- 所有出现 / 过渡 / 消失都做平滑处理：卡片入场用轻微上移淡入，筛选切换用布局过渡，滚动时不做视差干扰。
- 全部动效在 `prefers-reduced-motion: reduce` 下关闭。
- 交互反馈完整：悬停、按下、键盘聚焦环、加载中、成功与失败状态均有明确表现。
- 低性能设备：只使用 transform 与 opacity 动画，避免触发布局重排。

## 7. 来源收敛

新增 `scripts/sources/config.ts`，用声明式配置管理启用来源，替代目前散落在各 adapter 里的硬编码列表。

默认启用：

- 一线实验室官方：OpenAI、Anthropic、Google DeepMind、Meta AI。
- 聚合与研究：HuggingFace Papers、Hacker News。
- 论文：arXiv cs.CL / cs.LG（底座已支持，保持按需开启）。
- 中文来源：精选 1–2 个权威来源（如机器之心、量子位 RSS）。

保留底座的 adapter 接口（`scripts/sources/types.ts`）与"单源失败不影响整体"的并行抓取策略。增删来源只改配置文件。

## 8. 错误处理

| 场景 | 行为 |
| --- | --- |
| 单个来源抓取失败 | 跳过该源，其余正常，元数据记录错误（底座已有） |
| LLM 调用超时 / 非 200 | 重试 1 次，仍失败则该批走规则打分 |
| LLM 返回非法 JSON | 剥离代码块围栏后重试解析；仍失败则走规则打分 |
| 未配置 API Key | 全部走规则打分，站点照常运行 |
| 评分结果越界（分数 < 0 或 > 100） | 裁剪到 0–100 |
| 写入快照失败 | 中止该次运行，保留上次线上版本 |
| 静态构建失败 | 本次不部署，线上继续提供上一次成功版本 |
| 失效来源过多 | 沿用底座阈值告警，Actions 里显式标红 |

## 9. 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LLM_API_KEY` | — | 兼容任意 OpenAI 风格接口的密钥（`DEEPSEEK_API_KEY` 亦可） |
| `LLM_BASE_URL` | `https://api.deepseek.com` | 可切换到其他兼容服务 |
| `LLM_MODEL` | `deepseek-chat` | 打分与点评所用模型 |
| `SIGNIFICANCE_THRESHOLD` | `80` | 进入时间线的分数线 |
| `SIGNIFICANCE_MAX` | `60` | 每日 AI 评分条数上限 |
| `SIGNIFICANCE_CONCURRENCY` | `4` | 并发批次数 |
| `SIGNIFICANCE_TIMEOUT_MS` | `30000` | 单次请求超时 |

## 11. 部署与运维

- 用户需创建自己的 GitHub 仓库并推送本项目。
- Pages 的 Source 设为 GitHub Actions。
- 仓库 Secrets 配置 `DEEPSEEK_API_KEY`（或对应 provider 的密钥）。
- 工作流沿用底座的每日定时任务，保持北京时间早晨更新。
- 成本：每天 1 次运行、约 30–60 次 LLM 调用，按 DeepSeek 价格约每天几分钱到几毛钱。

## 12. 验收标准

1. `npm test` 全绿（含新增两组测试）。
2. `npm run crawl`（不配 Key）成功产出 `data/items.json`，条目带 `significance` 字段，时间线非空或为空时有明确日志说明。
3. 配置 Key 后，未缓存条目中 ≥ 90% 带 AI 评分（`method = "ai"`）。
4. `npm run build` 成功，静态导出目录生成。
5. 首页在 1280 / 768 / 375 三种宽度下无横向滚动，双栏正确折叠为单栏。
6. 键盘可完整操作筛选与链接，焦点可见。
7. 开启"减少动态效果"后无入场动画。

## 13. 风险与对策

| 风险 | 对策 |
| --- | --- |
| LLM 输出 JSON 不稳定 | 严格 schema 校验 + 解析失败降级规则打分 |
| 阈值过高导致时间线长期为空 | 阈值可配置；首周观察后校准 |
| 阈值过低导致时间线沦为普通信息流 | 规则兜底天然偏高门槛；prompt 中明确列出反例 |
| 评分把传闻当成重大事件 | prompt 明确排除未证实爆料；`reason` 字段保留判定理由便于回溯 |
| 上游项目更新产生冲突 | 改动集中在新文件，对底座文件的修改保持最小化，便于后续合并 |
| 来源改版导致抓取失效 | 沿用死源告警，配置文件内可快速增删 |
